## v0.2.2 · 2026-08-20 · 校时回写修复：芯片漂移恒慢的根因

> 取证链：串口探针 `TIME?` 实测**系统钟与 Mac 只差 1~2s**（App 自动校时已生效），但屏幕恒慢 6 分钟——屏幕直读 PCF85063 芯片，即「系统被修对、芯片从未被写」。顺藤摸到 v0.1.3 的 rtcBegin：

- **根因（一行级，潜伏 v0.1.3→v0.2.1 四个版本）**：rtcBegin 成功分支（ACK+OS=0 采纳芯片时间）`return true` 时**漏置 `rtcPresent_ = true`**——只有「芯片失效走编译兜底」分支置位。于是健康机体的 `rtcSet()` 全部在 `if (!rtcPresent_) return;` 静默跳过芯片写回：SETTIME 只修系统钟/文件名，芯片带着旧漂移继续跑。**验收盲区**：v0.1.4 时间链路验收只看「文件名正确」——文件名走系统钟，对芯片写回完全无感；屏幕（芯片）的 6 分钟漂移 = 数日累积
- **修复**：成功分支补 `rtcPresent_ = true`；`rtcWrite` 返回 I2C 成败、`rtcSet` 返回芯片写回结果（bool），校时日志区分「完成（系统+芯片 ✓）」与「半成（系统已设，芯片写回失败）」——此类静默失败从此可见；rtcRead 失败先重试一次再走编译兜底（防瞬态毛刺误判拿编译时间覆盖好芯片）
- 验证：烧 0.2.2 → 插线（App 自动 SETTIME）→ 串口见「校时完成（系统 + 芯片写回 ✓）」、屏幕一分钟内对齐；再拔线长按 PWR 真关机 → 重开机屏幕时间仍对（芯片已真写、电池存活）
- **屏幕版式重排**（用户定案，并入 0.2.2）：顶栏左 = 时钟（分钟沿走字，原在底栏）/ 右 = **电池**（图标+纯数字，去掉 % 后缀，右对齐）；底栏左 = **固件版本 v0.2.2**（烧没烧对一眼可见，呼应本次三连排查）/ 右 = 今日条数（不变）。顶栏旧的状态点+状态名删除——主体区已有大字状态，重复无信息量

## v0.2.1 · 2026-08-20 · 清理事务补齐（v0.2.0 首烧反馈）

> 起因两件：① v0.2.0 首烧实测——U 盘挂载/识别/同步全通，但 App「清理设备」还是读卡器时代的 `rmSync` 直删，撞只读卷全线 EROFS；② App 端 CDC 扫口 VID 匹配写错（板型 variant 写死 USB_VID=0x2886/Seeed，不是 Espressif 默认 0x303a），「未找到设备串口」。首版 0.2.0 已在设备上运行且不带下述能力——**升 0.2.1 让 App（设备卡「固件」栏，.echo-pod fw 字段开机自动刷新）可判别新旧固件**。

- **固件新增清理事务命令**（协议 v1.2 §6）：`RMBEGIN`（退盘，固件独占卡）→ `RM:<relPath>`×N（仅放行 `echo-pod/` 下 `.wav`，拒绝 `..`/`.`，`.logs` 不可达，逐条应答 `RM OK/ERR`）→ `RMEND`（顺手清空日期目录 + 复挂盘——host 重挂即见干净 FAT，无陈旧目录缓存）
- **App**：清理走 `cleanDeviceViaCdc()` 事务会话（返回「设备确认已删数」）；扫口 VID 修正（`2886`/`303a` 双认 + manufacturer 兜底 + 0x 前缀归一）；清理前固件版本门槛（<0.2.1 明确报「请重烧」）；全程无 RMBEGIN 应答也报「固件过旧」；断连判定去抖（事务退盘 1~3s，连续 2 轮 ≥4s 不见才判离，防 UI 闪「已断开」）
- **清理事务改严格一问一答**（0.2.1 首验第二课）：App 原实现收到 RM BEGIN 后一口气写 N 条命令，设备侧 CDC 接收缓冲仅 256B（≈5 条），溢出丢字节/熔行——失败清单里出现 `echo-RM:echo-pod/…`、`e1-18-33.wav` 等拼接残渣即此。改为收到上一条应答再发下一条（单命令在途，物理上不可能再溢出）；固件侧顺手把 CDC 接收缓冲 256→1024B 加固。**此修复纯 App 侧生效，无需重烧**
- **一问一答版实测通过**（第三轮）：清理事务 12+ 文件全删成功（卡上目录只剩清理后新录的两段），内核目录视图干净（卷确实完整经历卸载-重挂）。遗留两点收尾：① Finder **窗口**滞留旧目录——复挂空窗太短 macOS 可能没走完卸载，固件 RMEND 改**延迟 4s 复挂**（tick 到点执行，拔线/退盘即取消待复挂），逼 host 完成卸载后全新挂载；② 重启后头两条卡日志时间戳显示 UTC（14:25 vs 本地 22:25，差 8h）——TimeSync 设 TZ 晚于 pod_log 首写，`setenv("TZ")/tzset()` 提前到 setup 开头（此前「时间并没有对上」的观感即此，时钟本身一直是对的：录音文件名全程正确）
- 教训归档（Journey）：**只读存储设备的协议必须一开始把"写类操作"（删除/重命名）收进控制通道**；依赖 USB VID 认设备要先实证——板型 variant 可以写死任意 VID；**串口命令协议批量下发必须一问一答或分帧确认**，CDC 小缓冲 + newlib 丢字节是静默的

## v0.2.0 · 2026-08-20 · 阶段 2 同步链路

### USB 复合设备：插电脑 = 只读 U 盘 + 串口（TinyUSB 切栈）

- **切栈**：`ARDUINO_USB_MODE 1→0`（硬件 CDC → TinyUSB OTG）。MSC 接口注册的时机机制：`pod_usb.cpp` 全局 `USBMSC` 对象**构造期**（先于 `app_main`）注册进复合描述符，核心引导期 `USB.begin()` 一次成型 CDC+MSC——`ARDUINO_USB_ON_BOOT` 在 USB.h 里是无保护表达式重定义，`-D` 覆盖不了，靠构造时序取胜（platformio.ini 注释留档）
- **SYNC 态语义兑现**（v0.1.x 只占位）：插电脑 → 切段收尾当前文件（FAT 落盘干净）→ `mediaPresent(true)` 挂**只读** U 盘（`isWritable(false)` + onWrite 恒拒）→ 录音暂停；拔线退盘复录。取录音不再需要读卡器
- **互斥铁律落地**（software-spec「同一时刻 SD 只归一方」）：挂盘期间固件侧零 SD 访问——recorder 暂停、`pod_log` 关卡写（`setCardEnabled(false)`，串口照常）、SD 热拔探测跳过；MSC 读回调是唯一访问者（`sdmmc_read_sectors` 直读，host 侧只读 → 双向永不写冲突）
- **插线判定换源**：`Serial.isPlugged()`（HWCDC SOF，TinyUSB 下不存在）→ `pod::usb::hostOnline()`（`ARDUINO_USB_STARTED/STOPPED` 事件 + SUSPEND 3s 判离）。语义对齐：插电脑即真 / 插哑充电头即假（照常录音）/ host 休眠视同拔线退盘复录（与旧 SOF 超时一致）
- **新模块 `pod_usb.{h,cpp}`**（src/ 板卡服务层）：MSC 元数据/回调 + 插拔事件跟踪 + suspend 判离；debug env 永不 `storageAttach` → 插线仅供电+串口，契约不变

### CDC 自动校时通道（App 侧配套）

- 固件新增 `HELLO`（应答 fw/hw/serial，与 `.echo-pod` 标志文件同源）与 `TIME?`（回当前 Unix 秒）两个串口命令（经 TimeSync onLine 通道，协议入 device-protocol v1.2）
- App（Echo Pod Desktop）：设备插入沿（卷出现）→ 扫 VID 0x303a 串口 → HELLO 握手 → 无条件下发 `SETTIME:<电脑秒>` → 关口。每次插线把 PCF85063 拉齐电脑时间，±20ppm 漂移不累积；失败静默不阻塞同步主流程
  -（v0.2.1 勘误：VID 实为板型写死的 0x2886，扫口修正见 v0.2.1——首烧期间自动校时同样未生效）

### 固件内 SD 格式化（firmware-plan B6 兑现）

- **入口**：ERROR 态（SD 挂载失败）长按 BOOT 5s——v0.1.x「请用电脑格式化」占位兑现。`WavRecorder::rescueMount(format=true)`：卸载重挂，挂载失败则 IDF `format_if_mount_failed`（f_mkfs FAT）重来；成功后 `esp_restart()` 重走开机流（录音链路 + ensureMarker 开卡）
- **防误格由构造保证**：格式化只发生在「挂载失败」路径；卡可读则原样挂回绝不 f_mkfs，且非 ERROR 态不存在格式化入口。双重确认 = 屏显异常页 + 5s 长按（字体集无「格式化」字模，反馈走串口日志）

### 烧录流程重验提示（切栈必读）

- USB CDC 从硬件外设换到 TinyUSB 软件栈：**esptool 烧录 / monitor 首次需重验**（TinyUSB CDC 支持 DTR/RTS 复位进下载模式）；万一进不去 bootloader，**按住 BOOT 插线**走 ROM 下载模式
- 「ARDUINO_USB_MODE redefined」编译警告属预期（板卡预置 =1 在前、此处 =0 在后生效；若 =1 生效则 `USB` 对象不存在、编译必失败——成功即自证）

## v0.1.5 · 2026-08-20

### v0.2.0 前打磨：电量重标定 + ⚡ 时序 + VAD 阈值定格 0.92 + 分钟沿走字

- **highThreshold 定格 0.92**（0.85 实测通过后用户分两步调参 0.98→0.92）：卡在摩擦上限 0.78 与闷声区 0.85~0.95 的上沿——挡误触留余量；代价 = 特别闷/隔厚衣说话漏录，依据链全留 config 注释
- **分钟沿刷屏（时钟走字）**：每秒查 RTC 分钟、变化才 renderPage——屏幕时钟从「事件驱动才更新」变为每分钟走字；残影只来自变化的分钟数字，同分钟零驱动；600ms 阻塞由 2s 预滚环吸收（切段刷屏同机制已验证）；电量百分比随每分钟刷新自然跟进。功耗增量 <0.2%（60 次/h 局部刷新 ≈ 0.02~0.08mA）

- **问题**：百分比与实际耐用度不线性——旧表 0%=3.00V 是永远到不了的虚构值（低电强制关机 ~3.6V 先发生，0~7% 显示不出，设备在「10%」附近就死）；3.77→3.68V 这 0.09V 承载 30%→10%，负载压降一来读数跳 20~30%；ADC 噪声直接透传显示
- **查表重标定**（4.2V 锂电 0.2C 放电曲线 + 本机现实）：0% 定 **3.60V**，断点 `4.20/4.08/4.00/3.94/3.89/3.85/3.82/3.79/3.76/3.72/3.60`；LOWBAT 8% 落 ≈3.70V（原 3.59V），断电余量更足
- **显示迟滞**：电压 EMA（α=0.3/次，60s 采样 ≈3min 时间常数）+ 放电棘轮（只降不升；充电自由升；跳升 >15% 视为换电/复位容错）。`b.volts` 保持原始值供日志核对
- **⚡ 图标时序修复**：插拔沿（enterSync/exitSync）先取新鲜 `batterySample` 再刷屏——旧实现用 ≤60s 快照，⚡ 晚到/残留；60s 周期采样检测到充电态翻转也补一次刷屏
- ⚡ 语义留档：屏幕 ⚡ = USB **数据连接**在线（`Serial.isPlugged()`），非物理充电——插 dumb 充电头无主机枚举则不显示 ⚡（ETA6098 实际在充，红灯为权威指示；CHG 引脚未接 ESP，固件无法读真实充电态）
- 已知边界：电压法在锂电平台期（3.9~3.8V）本质分辨率有限，无电流计无法库仑计数——线性度改善但有物理上限；真实曲线以佩戴 `[bat]` 日志持续校准

## v0.1.4 · 2026-08-20 · e2d4f34 · 6a33b45（改动并入）· 版本归属收口 + 诊断修复

### VAD 触发重调：抗咳嗽/敲桌误触发

> 归属说明：本改动在并行工作线以 6a33b45 提交（当时暂占 0.1.2），与 v0.1.2/v0.1.3 时间线并行开发；合并后按预案归属 **v0.1.4**。完整分析存档见主仓库 `vad-tuning-pending-merge.md`（已标注合并）。

- **问题**：佩戴实测咳嗽、敲桌误触发录音；只调阈值（0.68/0.94）无效
- **根因**：① 150ms（5 帧）窗口对 0.3~0.6s 的咳嗽/连敲「透明」，占比被拉满；② release=0.92 慢泄使连环爆发跨间隙累积破阈值。咳嗽是声带发声，频谱上就是人声，VADNet 逐帧挡不住 → 只能时域治理
- **方案（防误触职责重新分工：窗口管「事件要长」，IDLE 快泄管「不累积」，attack 只管平滑）**：

| 参数 | 旧 | 新 | 说明 |
|---|---|---|---|
| `frameWindow` | 5（150ms） | **32（960ms）** | 窗口语义升级「语音密度」：单咳占比≈0.47、长咳≈0.63，均 <0.68 不触发；连续说话≈1.0 |
| `attack` | 0.94 | **0.70** | 抗误触移交窗口后回归快上升；触发延迟 ≈750ms < 2s 预滚，不丢首音 |
| `releaseIdle`（新增） | — | **0.75** | IDLE 态快泄 τ≈100ms，连咳/连敲间隙 score 掉光不累积；ACTIVE 仍 0.92（对话停顿不切段） |
| `MAX_WIN`（VadTrigger.h） | 16 | **48** | 窗口容量上限；不改则 32 会被 clamp 回 1 反而更灵敏 |

- **明确不动**：mid/low 阈值 0.30/0.20（停止逻辑）、hangover 6s、warmup、MODE_2、预滚 2s
- **highThreshold 跟进 0.68→0.85、midThreshold 0.30→0.55**（同日 `[vad+]` 实测数据驱动）：手摩擦外壳 VADNet 密度上限 ratio≈0.78、佩戴说话稳态 0.91~1.00——0.85 卡在中间，摩擦的 score 天花板够不着、说话正常触发。**能量门方案同时否决**：摩擦 peak 663~3960 与说话 152~1980 完全重叠（接触传导比 15cm 人声还响），且口袋布料摩擦 peak 仅 106~133（贴底噪）仍被判 0.25~0.47 密度——VADNet 输入归一化，能量域彻底无门限可设。mid 0.55 依据：摩擦 score 上限 0.46，旧值 0.30 下摩擦反复清零 hangover 造成 ~10s 噪声尾拖长；0.55 后真静音正常收尾、对话停顿仍受 6s hangover 保护
- **已知取舍**：孤立短句（<0.7s，如喊一声名字）可能不触发，需连续说话近 1s 才开录；与「咳嗽不触发」是同一时域判据的对称代价，对记录对话场景可接受
- **回退路径**：`attack=0.94 / frameWindow=5 / releaseIdle=0.92`（与 release 同值 = 状态无关衰减）即完全恢复 v0.1.1 行为
- **烧录验证清单**（串口 5s 心跳 `[vad] score=`）：① 咳嗽 1~5 声（含连环）峰值 <阈值 不触发 ② 连敲桌/摩擦外壳不触发 ③ 正常说话 ~1s 触发、回放首音完整 ④ 录音中停顿 <6s 不切段
- **边界**：窗口/包络只管时间结构（短瞬态），不管信号强度与来源距离——若未来出现「高密度伪人声」（>0.85 持续）需频谱层（摩擦=高频宽带 vs 人声=低频谐波，过零率/分带能量），能量层已证不可行

### 诊断通道补全：卡日志落盘修复 + 插线可监听

> 起因：佩戴桌测反馈「日志写了个寂寞」+「插着线根本不会录音，没法抓串口」。取证发现两处设计缺陷叠加。

- **fsync 修复（卡日志断电全丢）**：`fflush()` 在这套栈上只刷 newlib 缓冲到 FatFS 内存缓存，**FAT 目录项不更新**——断电后文件长度归零、内容不可见（8-18/8-20 两个 0 字节日志即此；8-19 有内容属写入量运气）。`event()` 补 `fsync()`（VFS→f_sync，数据+目录项真正落盘），事件级低频可承受
- **`LISTEN:1/0` 串口命令**（经 TimeSync 通用行转发通道）：插线默认进 SYNC 暂停录音，把「边连串口边观测 VAD」堵死。`LISTEN:1` 挂起自动同步策略、插线保持监听（诊断用）；`LISTEN:0` 恢复
- `[rec] >>>` 触发行补 `peak=`（触发时音频峰值，能量门调参依据）
- 空闲时 `[vad]` 心跳每 30s 落卡一份（电池场景无串口也能复盘灵敏度；录音中不写卡防干扰 WAV 顺序写）
- 启动失败若 SD 已挂载也开卡日志（此前音频阶段失败全程无留痕）
- **`echo-pod-debug` 调试 env**（编译期 `POD_DEBUG=1`，与 release 同一份 src）：插线仅=供电+串口，永不进 SYNC 态、录音/日志不中断——调试观测专用；串口横幅与参数 dump 标注 `debug` 构建。烧录：`pio run -e echo-pod-debug -t upload`
  - debug 专属 **500ms 高频心跳 `[vad+] ratio= score= peak= lowMs=`**（仅串口，条件编译，release 零开销）：ratio=窗口原始语音占比（包络前）/ score=包络后 / peak=音频峰值三层分开看，能量门与阈值调参依据。配套 VadTrigger 新增 `getRatio()` 观测口

### 诊断可观测性修复 + ERROR 页重绘

> 起因：v0.1.4 首次烧录即遇 I2C 总线卡死——esptool 复位瞬间总线事务半空，SDA+SCL 双双被拉低（第二次同类事件，v0.1.0 时仅 SDA）。9 时钟恢复对「SCL 也被咬住」无效，RTC/ES8311/SHTC3 全部探测失败。**唯一解 = 长按 PWR 真断电再开机**（外部芯片断电复位；RTC 电池直供时间不丢），无需重烧。

- **错误归因修正**：SD 挂载在 begin() 里先于 ES8311 且当时已成功，真因是 codec（I2C）——但 main.cpp 标签写死「[sd] 初始化失败」误导排障。改为「录音链路初始化失败（原因见上方错误行）」

## v0.1.2 · 2026-08-20 · 14708bb

### 修复：录音文件日期永远停在编译日（v0.1.1 佩戴发现）
