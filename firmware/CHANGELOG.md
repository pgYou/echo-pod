## v0.1.5 · 2026-08-20

### v0.2.0 前打磨：电量重标定 + ⚡ 时序 + VAD 阈值定格 0.92 + 分钟沿走字

- **highThreshold 定格 0.92**（0.85 实测通过后用户分两步调参 0.98→0.92）：卡在摩擦上限 0.78 与闷声区 0.85~0.95 的上沿——挡误触留余量；代价 = 特别闷/隔厚衣说话漏录，依据链全留 config 注释
- **分钟沿刷屏（时钟走字）**：每秒查 RTC 分钟、变化才 renderPage——屏幕时钟从「事件驱动才更新」变为每分钟走字；残影只来自变化的分钟数字，同分钟零驱动；600ms 阻塞由 2s 预滚环吸收（切段刷屏同机制已验证）；电量百分比随每分钟刷新自然跟进。功耗增量 <0.2%（60 次/h 局部刷新 ≈ 0.02~0.08mA）

- **问题**：百分比与实际耐用度不线性——旧表 0%=3.00V 是永远到不了的虚构值（低电强制关机 ~3.6V 先发生，0~7% 显示不出，设备在「10%」附近就死）；3.77→3.68V 这 0.09V 承载 30%→10%，负载压降一来读数跳 20~30%；ADC 噪声直接透传显示
- **查表重标定**（4.2V 锂电 0.2C 放电曲线 + 本机现实）：0% 定 **3.60V**，断点 `4.20/4.08/4.00/3.94/3.89/3.85/3.82/3.79/3.76/3.72/3.60`；LOWBAT 8% 落 ≈3.70V（原 3.59V），断电余量更足
- **显示迟滞**：电压 EMA（α=0.3/次，60s 采样 ≈3min 时间常数）+ 放电棘轮（只降不升；充电自由升；跳升 >15% 视为换电/复位容错）。`b.volts` 保持原始值供日志核对
- **⚡ 图标时序修复**：插拔沿（enterSync/exitSync）先取新鲜 `batterySample` 再刷屏——旧实现用 ≤60s 快照，⚡ 晚到/残留；60s 周期采样检测到充电态翻转也补一次刷屏
- ⚡ 语义留档：屏幕 ⚡ = USB **数据连接**在线（`Serial.isPlugged()`），非物理充电——插 dumb 充电头无主机枚举则不显示 ⚡（ETA6098 实际在充，红灯为权威指示；CHG 引脚未接 ESP，固件无法读真实充电态）
- 已知边界：电压法在锂电平台期（3.9~3.8V）本质分辨率有限，无电流计无法库仑计数——线性度改善但有物理上限；真实曲线以佩戴 `[bat]` 日志持续校准

## v0.1.4 · 2026-08-20 · e2d4f34 · 6a33b45（改动并入）· 版本归属收口 + 诊断修复

### VAD 触发重调：抗咳嗽/敲桌误触发

> 归属说明：本改动在并行工作线以 6a33b45 提交（当时暂占 0.1.2），与 v0.1.2/v0.1.3 时间线并行开发；合并后按预案归属 **v0.1.4**。完整分析存档见主仓库 `vad-tuning-pending-merge.md`（已标注合并）。

- **问题**：佩戴实测咳嗽、敲桌误触发录音；只调阈值（0.68/0.94）无效
- **根因**：① 150ms（5 帧）窗口对 0.3~0.6s 的咳嗽/连敲「透明」，占比被拉满；② release=0.92 慢泄使连环爆发跨间隙累积破阈值。咳嗽是声带发声，频谱上就是人声，VADNet 逐帧挡不住 → 只能时域治理
- **方案（防误触职责重新分工：窗口管「事件要长」，IDLE 快泄管「不累积」，attack 只管平滑）**：

| 参数 | 旧 | 新 | 说明 |
|---|---|---|---|
| `frameWindow` | 5（150ms） | **32（960ms）** | 窗口语义升级「语音密度」：单咳占比≈0.47、长咳≈0.63，均 <0.68 不触发；连续说话≈1.0 |
| `attack` | 0.94 | **0.70** | 抗误触移交窗口后回归快上升；触发延迟 ≈750ms < 2s 预滚，不丢首音 |
| `releaseIdle`（新增） | — | **0.75** | IDLE 态快泄 τ≈100ms，连咳/连敲间隙 score 掉光不累积；ACTIVE 仍 0.92（对话停顿不切段） |
| `MAX_WIN`（VadTrigger.h） | 16 | **48** | 窗口容量上限；不改则 32 会被 clamp 回 1 反而更灵敏 |

- **明确不动**：mid/low 阈值 0.30/0.20（停止逻辑）、hangover 6s、warmup、MODE_2、预滚 2s
- **highThreshold 跟进 0.68→0.85、midThreshold 0.30→0.55**（同日 `[vad+]` 实测数据驱动）：手摩擦外壳 VADNet 密度上限 ratio≈0.78、佩戴说话稳态 0.91~1.00——0.85 卡在中间，摩擦的 score 天花板够不着、说话正常触发。**能量门方案同时否决**：摩擦 peak 663~3960 与说话 152~1980 完全重叠（接触传导比 15cm 人声还响），且口袋布料摩擦 peak 仅 106~133（贴底噪）仍被判 0.25~0.47 密度——VADNet 输入归一化，能量域彻底无门限可设。mid 0.55 依据：摩擦 score 上限 0.46，旧值 0.30 下摩擦反复清零 hangover 造成 ~10s 噪声尾拖长；0.55 后真静音正常收尾、对话停顿仍受 6s hangover 保护
- **已知取舍**：孤立短句（<0.7s，如喊一声名字）可能不触发，需连续说话近 1s 才开录；与「咳嗽不触发」是同一时域判据的对称代价，对记录对话场景可接受
- **回退路径**：`attack=0.94 / frameWindow=5 / releaseIdle=0.92`（与 release 同值 = 状态无关衰减）即完全恢复 v0.1.1 行为
- **烧录验证清单**（串口 5s 心跳 `[vad] score=`）：① 咳嗽 1~5 声（含连环）峰值 <阈值 不触发 ② 连敲桌/摩擦外壳不触发 ③ 正常说话 ~1s 触发、回放首音完整 ④ 录音中停顿 <6s 不切段
- **边界**：窗口/包络只管时间结构（短瞬态），不管信号强度与来源距离——若未来出现「高密度伪人声」（>0.85 持续）需频谱层（摩擦=高频宽带 vs 人声=低频谐波，过零率/分带能量），能量层已证不可行

### 诊断通道补全：卡日志落盘修复 + 插线可监听

> 起因：佩戴桌测反馈「日志写了个寂寞」+「插着线根本不会录音，没法抓串口」。取证发现两处设计缺陷叠加。

- **fsync 修复（卡日志断电全丢）**：`fflush()` 在这套栈上只刷 newlib 缓冲到 FatFS 内存缓存，**FAT 目录项不更新**——断电后文件长度归零、内容不可见（8-18/8-20 两个 0 字节日志即此；8-19 有内容属写入量运气）。`event()` 补 `fsync()`（VFS→f_sync，数据+目录项真正落盘），事件级低频可承受
- **`LISTEN:1/0` 串口命令**（经 TimeSync 通用行转发通道）：插线默认进 SYNC 暂停录音，把「边连串口边观测 VAD」堵死。`LISTEN:1` 挂起自动同步策略、插线保持监听（诊断用）；`LISTEN:0` 恢复
- `[rec] >>>` 触发行补 `peak=`（触发时音频峰值，能量门调参依据）
- 空闲时 `[vad]` 心跳每 30s 落卡一份（电池场景无串口也能复盘灵敏度；录音中不写卡防干扰 WAV 顺序写）
- 启动失败若 SD 已挂载也开卡日志（此前音频阶段失败全程无留痕）
- **`echo-pod-debug` 调试 env**（编译期 `POD_DEBUG=1`，与 release 同一份 src）：插线仅=供电+串口，永不进 SYNC 态、录音/日志不中断——调试观测专用；串口横幅与参数 dump 标注 `debug` 构建。烧录：`pio run -e echo-pod-debug -t upload`
  - debug 专属 **500ms 高频心跳 `[vad+] ratio= score= peak= lowMs=`**（仅串口，条件编译，release 零开销）：ratio=窗口原始语音占比（包络前）/ score=包络后 / peak=音频峰值三层分开看，能量门与阈值调参依据。配套 VadTrigger 新增 `getRatio()` 观测口

### 诊断可观测性修复 + ERROR 页重绘

> 起因：v0.1.4 首次烧录即遇 I2C 总线卡死——esptool 复位瞬间总线事务半空，SDA+SCL 双双被拉低（第二次同类事件，v0.1.0 时仅 SDA）。9 时钟恢复对「SCL 也被咬住」无效，RTC/ES8311/SHTC3 全部探测失败。**唯一解 = 长按 PWR 真断电再开机**（外部芯片断电复位；RTC 电池直供时间不丢），无需重烧。

- **错误归因修正**：SD 挂载在 begin() 里先于 ES8311 且当时已成功，真因是 codec（I2C）——但 main.cpp 标签写死「[sd] 初始化失败」误导排障。改为「录音链路初始化失败（原因见上方错误行）」
- **回调时序修正**：`recorder.onError/onStateChange` 注册提前到 `begin()` 之前——此前 begin 阶段的 notifyError 细节（SD 挂载 err 码 / ES8311 / I2S）被吞，只剩笼统标签
- **ERROR 页重绘**：去掉矩形双线框；文案从「无卡或卡异常/请用电脑格式化」（归因不当）改为通用「设备异常 / 长按PWR键关机」+ 感叹号图标；字库 labels 同步更新（中文 56 字）
- README 烧录小节补充「烧录后 I2C 卡死 → 真断电重启即恢复」

- 状态：✅ 已实测（2026-08-20 佩戴验证，用户确认「改善很多」：摩擦不触发、说话正常触发、口袋噪声尾收敛）。文件名落当日目录且时间正确——v0.1.2/v0.1.3 时间链路修复经实测一并闭环

## v0.1.2 · 2026-08-20 · 14708bb

### 修复：录音文件日期永远停在编译日（v0.1.1 佩戴发现）

- **根因**：`TimeSync::begin()` 无条件 `setRtcFromCompile()` → `settimeofday(编译时刻)`，每次开机把 `rtcBegin()` 刚设好的有效芯片时间砸掉。屏幕直读芯片所以一直正确，极具迷惑性
- **取证**：SD 卡 `.logs` 同次开机时间戳倒跳（芯片 02:05:17 → 编译 20:55:25）；两次开机（相隔 3h）后续戳完全相同 = `__TIME__` 常数；芯片两次读数精确走 3h07m → 芯片健康，被砸的只是系统时间
- 修复：删 `setRtcFromCompile`；`sync()` 不再自设时间，经回调交付
- `pod::rtcSet()` 成为统一校时入口：settimeofday + 写芯片一次完成；入口守卫拒绝 <2020-01-01 异常值
- 状态：被 v0.1.3 取代，未单独烧录
